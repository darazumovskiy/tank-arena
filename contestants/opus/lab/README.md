# Лаборатория «Оракула»

Инструменты, которыми танк проверялся и настраивался. На бой не влияют: судья берёт только `tank/`.

- `run.mjs` — параллельные матчи A против B со статистикой (победы, урон, точность, перехваты, аптечки, зона).
  `node lab/run.mjs --a tank --b lab/opponents/fable --matches 16 --rounds 8`
  Ключи: `--sa/--sb "броня,двигатель,пушка,перезарядка"`, `--pa/--pb "ключ=значение"` (параметры `bot._P`),
  `--spread 60` (случайный сдвиг старта, по умолчанию включён), `--seed`, `-v` (раунды поштучно).
  Для воспроизводимости разбора добавляйте `--pa budget=1000 --pb budget=1000`: иначе при нагрузке срабатывает бюджет времени и поведение зависит от загрузки машины.
- `trace.mjs` — трасса одного раунда матча (позиции, режим, цель, выстрелы, рикошеты, перехваты), `--dump тик` раскладывает стоимость планов.
- `analyze.mjs` — все попадания с дистанцией и временем полёта; для нашего танка — видел ли планировщик уход.
- `dodgecheck.mjs` — перебором 5000 манёвров на настоящем движке проверяет, можно ли было увернуться от попавшей пули.
- `spikes.mjs` — распределение времени тика и профиль по секциям.
- `browser/` — проверка в настоящем Web Worker: `node lab/browser/server.mjs`, затем открыть
  `http://localhost:8765/lab/browser/test.html?rounds=4` (результат придёт POST-запросом в `browser/result.json`).
- `opponents/` — независимые соперники: `fable` («Ртуть»), `sonnet` («Резонанс»), `haiku` («Хаику») написаны отдельными агентами без доступа к нашему коду; `rusher` («Таран») — Охотник, лезущий в упор.
- `snap/` — снимки нашего бота на этапах разработки для сравнения версий.
- `preview.html` — превью внешнего вида.
